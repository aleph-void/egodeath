// JavaScript obfuscator · CLI & library

Make Your JavaScript
Unreadable to Humans and LLMs

egodeath rewrites your code through a 20-transform pipeline: flattened control flow, identifiers drawn from 16 Unicode scripts, a chained-XOR string table and dead code cloned from your real statements. The program still runs. Reading it is another matter.

$ npm install -g egodeath

Deterrence, not secrecy. egodeath does not achieve indistinguishability obfuscation. It raises the cost of reverse engineering; it does not prevent it. Never ship secrets in client-side code, obfuscated or not.

  let sum = 0;
  for (const p of parts) sum += parseInt(p, 16);
  return sum % 97 === 42;
}

// Features

Built to Waste an Analyst’s Time

Each transform targets a different shortcut a reader would take, whether that reader is a person with a debugger or a model with a context window.

Control Flow Flattening

Function bodies become while(true){switch(...)} state machines. Case labels are encoded through modular arithmetic with random primes, so the execution order isn’t written down anywhere.

Gentry, Lewko, Sahai, Waters

Unicode Identifiers

Every name is replaced with 6 to 16 random characters drawn from CJK, Hangul, Greek, Cyrillic, Devanagari, Thai, Arabic, Katakana and more. Good luck reading ᆄաþॕᄣڶ䏜ᅇ aloud.

Chained String Encryption

All strings move into one array. Each entry’s XOR key depends on the decoded content of the entry before it, with sparse, position-dependent errors mixed in. Unused decoys stay encoded.

Garg et al. · Ragavan et al.

Mutation-Based Dead Code

Dead code isn’t generic filler. egodeath clones your real statements and mutates their operators, constants and names, so the fake branches are structurally identical to the live ones.

Gentry, Lewko, Sahai, Waters

LLM Context Exhaustion

Expressions are wrapped in deeply nested ternaries with opaque conditions and void chains. A token budget can push output into the millions of tokens, past what a model can hold at once.

Anti-Debug & Self-Integrity

debugger traps on prime-number intervals, Function.prototype.toString checks and timing-anomaly detection. Tampering triggers busy waits, throws or silent corruption.

Bartusek, Malavolta

Punctured-Program Tripwires

Hidden checks compare parameter hashes against secret values using five hash patterns. On a match they corrupt state or stall, punishing anyone fuzzing your functions.

Sahai, Waters

LPN-Inspired Noise

Arithmetic gets random noise added and cancelled through split paths: add/sub, XOR, mul/div, hash chains and bit rotations. Intermediate values mean nothing until the whole path is traced.

Jain, Lin, Sahai

One Knob: Token Budget

--target-tokens sets the output size. Small inputs are bloated up to the budget; large inputs get less padding to stay within it. Heavier transforms switch on as the budget grows.

// Pipeline

Four Phases, Each Building on the Last

Your source is parsed once and passed through the pipeline in order. Later phases encode what earlier phases produced, so no layer can be peeled off on its own.

1

Anti-Analysis

Make dynamic analysis expensive.

  1. Anti-debug traps
  2. Punctured-program tripwires
  3. LPN noise injection
2

Structure

Destroy the shape of the code.

  1. Control flow flattening
  2. Opaque predicates
  3. Proxy function dispatch
  4. Context window exhaustion
  5. Comma expression merging
3

Identifiers

Erase every meaningful name.

  1. Catalog identifiers
  2. Substitute Unicode names
  3. Inject dummy parameters
4

Encoding

Hide every literal and lookup.

  1. Global variable encoding
  2. Property key encoding
  3. Number encoding (11 strategies)
  4. Self-integrity checks
  5. Chained-XOR string array
  6. Console stubs
  7. Terser minification

Dead code is injected throughout: extra switch cases in flattened functions, the false branches of opaque predicates, and standalone blocks, all scaled by the token budget.

What the Budget Turns On

The budget ratio compares the target size to your input. The dead-code multiplier scales from 1× at ratio 30 to 150× at 1,500 and above.

Budget ratioTransforms enabled
> 3Anti-debug, tripwires, control flow flattening, opaque predicates, comma merging
> 5Proxy functions, property key encoding, noise injection, self-integrity
> 8Context window exhaustion
> 10Global variable encoding

Ideas Borrowed from Cryptographic Obfuscation

Indistinguishability obfuscation is a theoretical construction that is far too slow to run. egodeath takes practical, heuristic techniques inspired by that literature. They are inspirations, not implementations of the proofs.

// Usage

A CLI and a Library

Requires Node.js 24 or 26 (^24.15.0 || ^26.0.0). Install it globally for the command line, or as a dependency to call from your build.

Command line

# Install
npm install -g egodeath

# Default budget: 2,000,000 tokens
egodeath input.js > output.js

# Compact output
egodeath --target-tokens 10000 input.js > output.js

# Maximum bloat
egodeath --target-tokens 10000000 input.js > output.js

Library

// npm install egodeath
const { obfuscate } = require('egodeath');

const source = 'function add(a, b) { return a + b; }';

// Returns the obfuscated source as a string
const out = obfuscate(source, {
  targetTokens: 10000,
});

Tested Against Real Packages

A compatibility tool clones each package, bundles it with webpack, obfuscates the bundle and runs the package’s own test suite against the result.

// FAQ

Frequently Asked Questions

Can I use it to protect API keys or other secrets?

No. egodeath does not achieve indistinguishability obfuscation, and nothing practical does. A determined analyst can run the code and watch what it does. Use it to deter casual copying and slow down reverse engineering, and keep real secrets on a server.

Does the obfuscated code behave the same?

That is the goal, and it is checked by 600+ unit tests plus a tool that runs real npm packages’ own test suites against their obfuscated bundles. There is one deliberate difference: every console method is replaced with a no-op, so obfuscated code does not log.

Will it run under a strict Content Security Policy?

Probably not. Global variable encoding and the anti-debug traps use eval, so a page that forbids 'unsafe-eval' will block them. egodeath is not designed for strict-CSP pages; if you use it there, the policy has to allow eval.

How big and slow does the output get?

As big as you let it. The sample on this page grows an 8-line function to about 64 KB at a 3,000-token budget; the default budget is 2,000,000 tokens. Flattened control flow, proxy dispatch and string decoding all add runtime cost, so pick the smallest budget that meets your needs and benchmark hot paths.

Why target LLMs specifically?

Models are now a common first step in reverse engineering: paste the bundle, ask what it does. egodeath fights that with output too large for a context window, meaningless identifiers in mixed scripts, and dead code indistinguishable from live code, so a summary of the code is likely to be a summary of noise.

Is it free?

Yes. egodeath is open source under the MIT license. Issues and pull requests are welcome on GitHub.
